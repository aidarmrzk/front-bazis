# Базис — заметки и задачи

SPA на Nuxt 4, Vue Composition API, TypeScript strict и Pinia.
Собственная адаптивная вёрстка на SCSS; без библиотек компонентов,
готовой истории изменений и плагинов синхронизации хранилища.

## Запуск

Нужен Node.js 24.15+ (рекомендуется 24.22.3 LTS) и npm 10+.

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Для production:

```bash
npm run build
npm run preview
```

## Docker

```bash
docker-compose up --build
# Современный вариант команды:
docker compose up --build
```

Приложение доступно на http://localhost:3000. Остановка:

```bash
docker compose down
```

Сборка выполняется в отдельном этапе. В финальный образ попадает только
готовая `.output`; сервер работает от пользователя `node`, есть healthcheck.
Данные находятся в браузере, контейнеру том не нужен. При смене домена или
порта браузер использует отдельное хранилище.

## Возможности

- `/`: заметки с заголовком, первыми тремя задачами и прогрессом.
  Статус задач в карточке доступен только для просмотра.
- `/notes/new`: создание; `/notes/:id`: редактирование существующей заметки.
  Для отсутствующего идентификатора показывается понятное состояние.
- Название, текст задач и их статус редактируются в черновике. Только
  «Сохранить изменения» изменяет базу заметок.
- Удаление, отмена редактирования и переход с несохранёнными правками требуют
  подтверждения. Диалоги закрываются по Escape, удерживают фокус, блокируют
  фон и возвращают фокус инициатору.
- Undo/redo через кнопки и Ctrl/Cmd+Z / Ctrl/Cmd+Shift+Z вне полей ввода.
  В input, textarea и contenteditable сохраняется нативная отмена текста.
- Пустой заголовок и пустые добавленные задачи не сохраняются. Заголовок
  ограничен 120 символами, текст пункта — 1000. Список задач может быть пустым.
  Пробелы по краям удаляются при сохранении.

## Структура и решения

```text
app/
  components/    карточки, поля, панель истории, модальное окно
  composables/   состояние черновика, диалоги, сценарии редактора
  lib/           типы, патчи, сессия ввода, схема, черновики, клавиатура
  pages/         две компактные страницы
  plugins/       инициализация и storage events
  stores/        сохранённые заметки и явные команды CRUD
  assets/styles/ собственные SCSS-стили
tests/unit/      регрессии доменной логики и работы с хранилищем
docs/            архитектура и этапы разработки
```

### История изменений

`EditorSession` группирует ввод в одном поле до blur, перехода к другому полю
или паузы 650 мс. Перед атомарной операцией накопленный ввод фиксируется.
`PatchHistory` хранит максимум 50 патчей: старое/новое значение поля либо
один вставленный/удалённый пункт с позицией. Полные копии заметок в истории
не хранятся. Пункты адресуются стабильными id, а не сдвигающимися индексами.
Новая правка сразу очищает redo. Сохранение и отмена сбрасывают историю.
`structuredClone` защищает границы сессии и значения патчей от внешних изменений.

### Хранилище и восстановление

`localStorage['notes-spa:data']` содержит `{ schemaVersion: 1, notes: [...] }`.
Существующая схема v1 поддерживается; для v0 предусмотрена миграция
`{ version: 0, notes: [{ items: [{ id, text, done }], ... }] }` в `todos/completed`.
Вся структура, даты и уникальность id проверяются при чтении. Неизвестная
версия или повреждение блокируют запись, сохраняя исходные данные.

База пишется синхронно только по явным командам сохранения/удаления, без
таймера между подтверждённым сохранением и фактической записью. Перед командой
база перечитывается, чтобы учитывать изменения других вкладок. Ошибки доступа
или квоты показываются пользователю, черновик при неудачном сохранении остаётся.

`sessionStorage['notes-spa:draft:<id>']` хранит версионированный черновик
конкретной вкладки. Запись отложена на 350 мс, при `pagehide` и размонтировании
ожидающая запись выполняется сразу. После перезагрузки предлагается восстановление.
Поддерживаются и черновики прежней версии приложения. Сохранение/отмена
останавливают отложенную запись до удаления черновика.

`storage`-события обновляют список заметок. Если открытая заметка удалена
или изменена в другой вкладке, редактор сохраняет локальные правки и предлагает
создать копию. Проверка `updatedAt` предотвращает перезапись замеченного
конфликта. localStorage не поддерживает транзакции между вкладками:
строго одновременные записи всё ещё могут конфликтовать; для такой гарантии
потребовалось бы транзакционное хранилище или сервер.

## Проверки

```bash
npm test
npm run test:coverage
npm run typecheck
npm run build
```

Vitest проверяет лимит истории, группировку ввода, undo/redo, вставку и удаление,
сброс истории, реактивную сессию, CRUD, квоту, чужие изменения, схемы и миграцию,
восстановление и очистку черновика, валидацию, клавиатуру и управление фокусом.
Отчёт покрытия — `coverage/index.html`. Порог для строк/функций/выражений — 85%,
для ветвей — 75%; в измерение входят `app/lib` и `app/stores`.

Дополнительно проверены production-сценарии в браузере: создание и сохранение,
перезагрузка с восстановлением, undo/redo, подтверждение ухода, Escape и возврат
фокуса, удаление во второй вкладке, сохранение копии, прямой отсутствующий URL,
адаптивность на ширине 390 px. Демонстрационные записи не включены в приложение.

Подробности: [архитектура](docs/architecture.md), [этапы](docs/implementation-plan.md).

Для транзитивных `readdir-glob → minimatch` и `jsdom → undici` закреплены
исправленные ветки через npm overrides. При обновлении родительских пакетов
эти ограничения следует пересмотреть; production-сборка и тесты проверяются
с тем же lock-файлом, который используется Docker.
